= Spring AI RAG Demo
:linkattrs:
:project-owner:   megadotnet
:project-name:    spring-ai-redis-demo
:project-group:   com.redis.demo
:project-version: 0.0.1-SNAPSHOT
:project-title:   Spring AI RAG Demo

---

基于 link:https://docs.spring.io/spring-ai/reference/[Spring AI] 和 link:https://milvus.io/[Milvus] 向量数据库的检索增强生成（RAG）演示应用，支持 **混合检索**（BM25 + 向量 + RRF 融合）、**Rerank 精排** 和 **Redis 持久化**。

应用同时提供**两条独立的问答通道**：单次检索的 Native 链路（`POST /chat/{chatId}`），以及带查询规划、多轮检索与引用校验的 Agentic 有界运行时链路（`POST /api/agent/chat`）。两者共用同一套检索栈与同一份 Redis 会话存储。

完整的架构解读、数据流、数据结构与前后端契约详见 link:Architecture.md[技术架构详解]。

== 技术架构

[source]
----
              ┌───────────────────────────────┐
              │  React UI (CRA, hash 路由)     │
              │  #/native        #/agentic    │
              └───────┬───────────────┬───────┘
        POST /chat/{chatId}    POST /api/agent/chat
                      │               │
              ┌───────▼──────┐  ┌─────▼───────────────┐
              │  RagService  │  │ AgentRuntimeService │
              │  异步，1 轮  │  │ 同步，最多 3 轮检索 │
              └───────┬──────┘  │ + QueryPlanner      │
                      │         │ + GroundingChecker  │
                      │         └─────┬───────────────┘
                      └────────┬──────┘
                               ▼
                   ┌───────────────────────┐
                   │  HybridSearchService  │
                   │   RRF 融合 + Rerank   │
                   └─────┬─────────────┬───┘
              ┌──────────▼───┐     ┌───▼────────────┐
              │ Lucene BM25  │     │ Milvus Vector  │
              │ （进程内索引）│     │ Store (COSINE) │
              └──────────┬───┘     └────────────────┘
                         │ 文档持久化
              ┌──────────▼───────┐   ┌─────────────────┐
              │ Redis            │   │ SiliconFlow     │
              │ · BM25 文档      │   │ · Rerank        │
              │ · 会话记忆       │   │ · DeepSeek-OCR  │
              └──────────────────┘   └─────────────────┘
----

WARNING: BM25 索引本体在 **Lucene 内存目录**（`ByteBuffersDirectory`）里，Redis 只存放用于重启后重建的文档正文（`bm25:doc:{docId}`，截断 2000 字符）。恢复时 `docId` 与 metadata 会丢失，因此重启后建议调用 `POST /admin/bm25/rebuild`。

=== 两条问答通道

两条通道共用同一套检索栈、同一份 Redis 会话存储与同一个 React 页面，仅控制流不同。

[cols="1,1,2"]
|===
| 维度 | Native | Agentic

| 端点
| `POST /chat/{chatId}`
| `POST /api/agent/chat`

| 服务类
| `RagService`
| `AgentRuntimeService`

| 执行模型
| 异步 `CompletableFuture` + `orTimeout(65s)`
| 同步（不受 async 超时层级保护）

| 检索轮数
| 严格 1 次
| 最多 `MAX_TOOL_CALLS = 3` 次

| 查询规划
| 无，直接用原始问题
| `QueryPlanner` 拆复合问题为子查询

| 请求体
| `{prompt}`
| `{sessionId, question, topK?}`

| 响应体
| `{message}`
| `{traceId, answer, evidence, plan, grounded}`（`api.js` 将 `answer` 镜像为 `message`）

| 引用校验
| 无
| `GroundingChecker` 要求至少一个 `[证据 N]` 且 ID 全部可回查

| 前端入口
| `#/native`
| `#/agentic`（额外渲染可折叠证据面板）
|===

Agentic 是*有界*运行时而非开放式工具循环：所有上限都是 `AgentRuntimeService` 里的编译期常量（`MAX_TOOL_CALLS=3`、`DEFAULT_TOP_K=5`、`MAX_TOP_K=20`、`MAX_CONTEXT_CHARS=12_000`），控制流全部留在 Java，LLM 只写文本、从不决定下一个要调哪个工具。

行为通过接口选配，依赖缺失时自动降级：`RetrievalTool`（`HybridRetrievalTool` / `VectorOnlyRetrievalTool`，由 `hybrid.search.enabled` 决定）、`QueryPlanner`、`ConversationMemory`、`VectorStoreStrategy`。

== 前置条件

=== Docker

运行 Milvus 向量数据库：
[source,console]
----
docker compose up -d
----

=== Milvus 单机版

{project-name} 的 `docker-compose.yml` 已内置 Milvus v2.6.7 单机版所需的三个容器，随上面的 docker compose up -d 一并启动；若只需先启向量库：

[source,console]
----
docker compose up -d etcd minio standalone
docker compose logs -f standalone
----

[cols="1,2,2"]
|===
| 服务 | 镜像 | 端口

| etcd
| quay.io/coreos/etcd:v3.5.5
| 2379（仅容器网络内访问）

| minio
| minio/minio:RELEASE.2023-03-20T20-16-18Z
| 9000 (S3) / 9001 (控制台)

| standalone
| milvusdb/milvus:v2.6.7
| 19530 (gRPC) / 9091 (metrics)
|===

standalone 未配置 healthcheck，docker compose ps 只会显示 running；需等到日志中 19530 端口开始监听后再启动应用。

连接地址：后端在宿主机用 127.0.0.1，在同一 compose 网络内用服务名 standalone（spring 服务已通过 SPRING_AI_VECTORSTORE_MILVUS_CLIENT_HOST 覆盖）；端口在 RagConfiguration 中固定为 19530。镜像拉取（含国内镜像源 retag）、数据卷与安全提示详见 link:DOCKER-README.md[Docker 部署指南]。

=== Ollama

安装并运行 link:https://ollama.com/[Ollama]，下载所需模型：
[source,console]
----
ollama pull qwen2.5:0.5b
ollama pull bge-m3:latest
----

其中 `bge-m3:latest` 是**必须**的：Embedding 始终由 Ollama 提供，没有它文档无法入库、查询无法向量化。`qwen2.5:0.5b` 仅在切回 `chat.provider=ollama` 时需要。

=== 硅基流动 API Key

从 link:https://cloud.siliconflow.cn/[硅基流动控制台] 获取 API Key。仓库默认 `chat.provider=openai` 指向硅基流动，且 Rerank 与 DeepSeek-OCR 也共用这个 Key，因此**本地跑起来就需要**，不再是可选项。

== 配置

=== 环境变量

[source,console]
----
# Chat / Rerank / DeepSeek-OCR 共用（必需）
export SILICONFLOW_KEY=<你的硅基流动API Key>

# Redis (会话记忆与 BM25 文档持久化)
export REDIS_HOST=<Redis 服务地址>
export REDIS_PORT=6379
export REDIS_PASSWORD=<Redis 密码>
----

NOTE: `REDIS_HOST` 只填主机名，不要把端口拼进去。若 Redis 不可用，BM25 持久化会自动熔断（`redisAvailable=false`）并降级为纯内存索引，应用仍可用。

=== 应用配置 (application.properties)

下面的片段摘自 `src/main/resources/application.properties`，注释标出了容易误改的项。该代码块特意关闭了属性替换，否则块内的美元符花括号环境变量占位符会被当成未定义属性而渲染为空。

[source,properties,subs="specialcharacters,macros,callouts"]
----
# --- 模型提供者配置 ---
# 可选值: ollama, openai；仓库当前值为 openai（非 ollama）
chat.provider=openai

# --- Ollama 配置 (当 chat.provider=ollama 时生效) ---
spring.ai.ollama.base-url=http://127.0.0.1:11434
spring.ai.ollama.embedding.options.model=bge-m3:latest
spring.ai.ollama.chat.options.model=qwen2.5:0.5b
spring.ai.ollama.connection-timeout=60s
spring.ai.ollama.read-timeout=60s
# Embedding 调用超时（Spring Boot 4.2 起 OllamaApi 默认请求工厂为 Reactor Netty，隐含约 10s 读超时）
spring.ai.ollama.embedding.connect-timeout=10s
spring.ai.ollama.embedding.read-timeout=300s

# --- OpenAI 兼容配置 (当 chat.provider=openai 时生效) ---
# 推荐使用环境变量 SILICONFLOW_KEY 设置 API Key（优先级高于 OPENAI_API_KEY）
spring.ai.openai.api-key=${SILICONFLOW_KEY:}
spring.ai.openai.base-url=https://api.siliconflow.cn
spring.ai.openai.chat.model=Qwen/Qwen3-8B

# --- Milvus 向量库配置 ---
# 本机运行后端填 127.0.0.1；compose 网络内填 standalone
spring.ai.vectorstore.milvus.client.host=192.168.0.223
spring.ai.vectorstore.milvus.collection-name=paper_collection_vpdf
spring.ai.vectorstore.milvus.embeddingDimension=1024

# --- RAG 检索配置 ---
# 初筛召回数量（混合检索内部取 max(topK*2, 20)）
topk=10
# Rerank 精排开关
rerank.enabled=true
rerank.model=BAAI/bge-reranker-v2-m3
rerank.topN=5

# --- 文档处理与切块配置 ---
# 切块算法: markdown (默认, 基于语义) 或 token (基于长度)
chunking.algorithm=markdown
chunking.markdown.chunkTokenNum=800
# 语义分割符；中文标点必须写成 \uXXXX 转义，否则 .properties 的 ISO-8859-1 读取会乱码
chunking.markdown.delimiter=\n!?;\u3002\uFF1B\uFF01\uFF1F
chunking.markdown.separateTables=true

# --- DeepSeek-OCR 配置 ---
deepseek-ocr.enabled=true
deepseek-ocr.model=deepseek-ai/DeepSeek-OCR

# --- 混合检索配置 (Lucene BM25 + Milvus Vector) ---
hybrid.search.enabled=true
hybrid.search.collection-name=paper_collection_vpdf
hybrid.search.rrf.k=60
hybrid.search.dense.weight=0.7
hybrid.search.sparse.weight=0.3

# --- Redis (会话记忆 + BM25 文档持久化) ---
spring.data.redis.host=${REDIS_HOST:localhost}
spring.data.redis.port=${REDIS_PORT:6379}
spring.data.redis.password=${REDIS_PASSWORD:}
spring.data.redis.ssl.enabled=false

# --- 异步链路超时，必须大于 RagController 的 orTimeout(65s) ---
spring.mvc.async.request-timeout=90000
----

WARNING: 并非所有看起来合理的配置项都生效。`RagConfiguration` 硬编码了 `MetricType.COSINE`、`IndexType.IVF_FLAT`、`databaseName("default")` 与端口 `19530`，所以 `spring.ai.vectorstore.milvus.metric-type=IP`、`client.port`、`index-type` 改了无效。

WARNING: 遗留耦合——`RagConfiguration` 仍注入 `${spring.ai.vectorstore.pinecone.index-name}` 且**没有默认值**。尽管已不用 Pinecone，`application.properties` 里的 `spring.ai.vectorstore.pinecone.*` 仍必须保留，删掉会导致应用**启动失败**。

NOTE: 超时阶梯是刻意设计的：上游模型读超时 60s < `orTimeout(65s)` < `spring.mvc.async.request-timeout=90000`。错位会导致对外 503，友好错误文案永远回不到前端。注意 `/api/agent/chat` 是同步端点，65s / 90s 两级均不适用。

== 运行

先构建前端。`pom.xml` 并未声明 `frontend-maven-plugin`（只有一个同名版本属性），实际是 `maven-resources-plugin` 在 `process-classes` 阶段把 `frontend/build` 拷进 `target/classes/static`，所以产物必须事先存在。

[source,console]
----
cd frontend
npm install

----

再启动后端。仓库内没有 Maven Wrapper，直接用本地 `mvn`：

[source,console]
----
git clone https://gitee.com/{project-owner}/{project-name}.git
cd {project-name}

----

WARNING: `Dockerfile` 的构建阶段仍写着 `RUN ./mvnw verify`，在补上 Maven Wrapper 或改为 `mvn verify` 之前无法构建成功。

== RAG 工作流程

Native 通道（`POST /chat/{chatId}`，异步，严格检索 1 轮）：

[source]
----
1. 用户提问
      │
2. 混合召回 (hybrid.search.enabled=true 时)
   ├── BM25 关键词检索 (Lucene 内存索引)
   └── 向量语义检索 (Milvus TopK)
      │
3. RRF 结果融合 (按 docId 聚合)
      │
4. Rerank 精排 (SiliconFlow topN=5) [可选，失败降级为原序]
      │
5. 拼装 prompts/system-qa.st + 上下文文档
      │
6. LLM 生成回答 (Ollama/OpenAI)
      │
7. 写入 Redis 会话记忆，返回 {message}
----

Agentic 通道（`POST /api/agent/chat`，同步，最多 3 轮检索）：

[source]
----
1. 读取会话历史 (RedisConversationMemory)
      │
2. RuleBasedQueryPlanner 拆分复合问题为子查询
      │
3. 逐个子查询调用 RetrievalTool (≤ MAX_TOOL_CALLS=3)
   ├── hybrid.search.enabled → HybridRetrievalTool (BM25 + 向量 + RRF)
   └── 否则               → VectorOnlyRetrievalTool
      │
4. EvidenceMapper 映射为 Evidence（取 rerank_score→score→distance→fusion_score）
      │
5. ContextBuilder 按 12000 字符预算拼装上下文
      │
6. AnswerGenerator 生成带 [证据 N] 引用的回答
      │
7. GroundingChecker 校验引用 ID 均可回查 → grounded 标志
      │
8. 返回 {traceId, answer, evidence, plan, grounded}
----

证据为空时不会调用 LLM，而是返回稳定的拒答文案。

== REST 端点

[cols="1,2,3"]
|===
| 方法与路径 | 作用 | 说明

| `POST /chat/startChat`
| 创建会话
| 返回 `{chatId}`；同时可当 agent 的 `sessionId` 使用

| `POST /chat/{chatId}`
| Native 提问
| 请求体 `{prompt}`，响应 `{message}`；异步 + `orTimeout(65s)`

| `GET /chat/history/{chatId}`
| 对话历史
| 返回 `{sessionId, messages[{role,content}]}`；无历史也返 200

| `POST /api/agent/chat`
| Agentic 提问
| 请求体 `{sessionId, question, topK?}`；响应 `answer` 由前端复制为 `message`

| `GET /api/agent/history/{sessionId}`
| Agentic 历史
| 与 Native 共用 `ConversationHistoryService`

| `POST /retrieve`
| 仅检索、不生成
| 供 Python 评测算 Context Recall

| `GET /admin/bm25/status`
| BM25 自检
| 内存/Redis/Milvus 三处计数、健康与一致性判定

| `POST /admin/bm25/rebuild`
| 重建 BM25
| 返回 `{success, bm25DocumentCount, message, error}`，失败为 500

| `POST /documents/upload`
| 上传入口
| *占位实现*，始终返回 `Document upload not supported`
|===

== 评测

两套独立的评测栈：

[source,console]
----
# Python / DeepEval：从 Milvus 切块合成 goldens，经 /retrieve 算 Context Recall
cd DeepEvalSpringAIRAG
pip install -r requirements.txt
python 1_generate_testset.py
python -m src.main

# Java / LLM-as-a-Judge：需 SILICONFLOW_KEY，否则自动跳过
mvn test -Dtest=FaithfulnessEvaluationTest
